# Vector UI Asset Pipeline

本文件定义当前项目后续按钮、面板、提示框等 UI 素材的生产方式。

目标只有两个：

1. 页面看起来像“控件”，不是“把一张图片贴上去”。
2. 后续能批量产出，不因为每个尺寸都单独修图而失控。

## 1. 当前问题的根源

你给出的按钮样式本身方向没错，但现阶段有两个结构性问题：

1. 按钮壳是完整位图贴图
   - 当前 `ThemePlaqueButton.vue` / `ThemeButton.vue` 直接把 `--theme-button-texture` 当整张背景使用。
   - 结果是只要宽高比稍有变化，就会出现两端被压缩、裁切、装饰断裂的问题。

2. 素材不是“透明壳”，而是“带环境底色的图片”
   - 粉色/白雾底如果烤进素材，页面上会明显看出它是一张图。
   - 真正的 UI 素材应该只承担边框、描边、局部纹样、内发光，不负责页面背景气氛。

## 2. 对这个项目最合适的方案

不要继续做“整张按钮 PNG”。

后续统一改成这套分层方式：

1. `结构层`
   - 代码负责圆角、尺寸、padding、hover、active、disabled。
   - 代码负责主底色、轻渐变、阴影、文字安全区。

2. `装饰层`
   - 使用矢量 SVG。
   - 只画边框、角花、端头云纹、金线、玉边、局部高光。
   - 中央区域保持干净，不能放固定纹样团。

3. `纹理层`
   - 如果需要细微纸纹、玉纹、绢纹，只作为可选叠层。
   - 透明度要低，不能主导形体。

结论：

- “按钮像按钮”靠的是代码结构。
- “修仙味道”靠的是矢量装饰层。
- 轻纹理只是辅助，不应成为主壳。

## 3. 按钮和面板不要做成一整张拉伸图

### 按钮

按钮推荐拆成三段，或者直接做成单个可拉伸 SVG：

1. 左端帽
2. 中段平直延展区
3. 右端帽

其中：

- 左右端承载复杂装饰
- 中段只允许非常轻的流纹/玉雾，不允许重花纹
- 文本始终落在中段安全区

如果用 SVG，优先两种实现：

1. 单文件 `SVG` + `preserveAspectRatio="none"`
   - 但复杂花纹必须避开中段
   - 适合长条按钮

2. `left / center / right` 三片式 SVG
   - 最稳
   - 适合后续所有按钮尺寸复用

对当前项目，推荐直接上三片式。

### 面板

面板不要拿一整张海报式图来当背景。

推荐两种方式：

1. 四角 + 四边 + 中心的 `9-slice`
2. 单个 SVG 面板壳，中央留净空

对当前项目，推荐：

- 主面板、剧情板、提示板走 `9-slice`
- 小卡片、轻提示走代码边框 + 小型 SVG corner ornaments

## 4. 建议的素材格式

首选格式：

1. `SVG`
   - 用于按钮壳、面板壳、徽章框、图标框
   - 必须透明背景
   - 必须可独立缩放

2. `PNG`
   - 只用于极轻的噪点、纸纹、云雾叠层
   - 不能承担结构边框

不推荐：

- 单张重装饰按钮 PNG
- 带粉底、带完整氛围背景的按钮图
- 把文字直接烤进素材

## 5. 一张图批量出素材的正确方式

你提到“可能很多素材图在一张图上”，这个是可行的，但不能是随便拼一张大图。

正确方式是做 `SVG sprite board / source board`：

1. 在一个矢量源文件里画整套母版
2. 每个资产单独有固定画板或命名分组
3. 导出时再拆成独立 SVG 文件

推荐组织方式：

1. `buttons-board.svg`
   - `btn-plaque-left`
   - `btn-plaque-center`
   - `btn-plaque-right`
   - `btn-plain-left`
   - `btn-plain-center`
   - `btn-plain-right`

2. `panels-board.svg`
   - `panel-story-corner-tl`
   - `panel-story-edge-top`
   - `panel-story-center`
   - `panel-tooltip-corner-*`

3. `frames-board.svg`
   - `icon-frame-jade`
   - `icon-frame-gold`
   - `badge-frame-rare`

注意：

- “一张图”适合当源文件，不适合直接当运行时背景图。
- 运行时仍然应当引用拆好的独立资源。

## 6. 本项目最值得先做的 4 套母版

先不要铺太多种类，先把母版做对。

### A. 按钮母版

至少做 3 类：

1. `plaque`
   - 用于主界“打坐修炼 / 突破境界 / 查看角色”
   - 端头更华丽，中心极干净

2. `plain action`
   - 用于确认、领取、推进、切换
   - 装饰更轻，适合高频使用

3. `danger / locked`
   - 用于不可用态、风险操作
   - 不单独重画结构，只改描边、光泽、色相

### B. 面板母版

至少做 3 类：

1. `surface panel`
   - 通用模块卡

2. `story panel`
   - 剧情文本板 / 事件板

3. `tooltip panel`
   - 小提示、悬浮说明、获得奖励

### C. 徽章 / 图标底

用于：

- 底部 tab
- 快捷入口
- 稀有度标记

### D. 小型分隔装饰

用于：

- 标题上下金线
- 区块分隔
- 对话框顶部小徽记

## 7. 视觉约束

为了避免继续出现“像图片”的问题，生成或绘制时必须遵守这些约束：

1. 素材背景必须透明
2. 中央必须留文字安全区
3. 装饰集中在边缘、角落、端头
4. 不允许出现完整场景底色
5. 不允许出现硬裁切痕迹
6. 不允许在中段放会被拉伸变形的复杂花纹
7. disabled / hover / active 优先通过代码做，不靠重新出整张图

## 8. 接入建议

后续代码层建议从“整张背景图”改成“结构 + 装饰资源”。

### ThemePlaqueButton

建议改成：

1. 外层按钮负责尺寸与交互
2. 内层用三个装饰片：
   - `.plaque-cap-left`
   - `.plaque-stretch`
   - `.plaque-cap-right`
3. 中央内容层单独叠放

这样可以保证：

- 宽按钮不会裁切
- 窄按钮不会把端头压坏
- 同一套素材可适配不同宽度

### ThemePanelFrame

建议改成：

1. 默认由代码画底板
2. 角花和边线由 SVG 分层叠加
3. 少数大主视觉面板才用完整主题图

## 9. 后续出图/出矢量时的提示词要求

如果后续要让模型生成母版，提示词必须明确：

- `transparent background`
- `vector UI asset`
- `reusable shell`
- `ornament only near edges`
- `clean center area for dynamic text`
- `no text`
- `no pink backdrop`
- `no full scene background`
- `no crop marks`
- `symmetrical horizontal button shell`
- `designed for stretchable game UI`

按钮额外要求：

- `decorated end caps`
- `flat readable center`
- `gold outline with pale jade enamel`

面板额外要求：

- `corner-focused ornament`
- `clean parchment-like center`
- `works as 9-slice panel shell`

## 10. 实际执行顺序

建议按这个顺序做，不要一上来铺全量：

1. 先定按钮母版结构
2. 再定面板母版结构
3. 再出一套统一角花/金线语言
4. 最后再补纹理、状态、色相变体

如果按钮和面板结构没定，后面出越多图，返工越大。

## 11. 对你当前截图的直接判断

你这张图的问题不是“美术不够好”，而是资产类型错了：

1. 按钮被当成完整图片在展示
2. 两端花纹进入了可拉伸区
3. 背景底色没有完全透明
4. 页面底板和按钮底板职责混在一起了

所以正确修法不是继续修这张 PNG，而是把它升级成：

- 透明背景的矢量按钮壳
- 端头装饰和中段延展分离
- 页面环境氛围交给 CSS / 页面背景

## 12. 最终推荐

对当前项目，最稳妥的路线是：

1. 后续 UI 壳类素材一律以 `SVG` 为主
2. 按钮一律按“三段式”设计
3. 面板一律按 `9-slice` 或“代码底板 + SVG 角饰”设计
4. 大图只作为源文件或氛围背景，不直接当按钮/面板运行时资源

这样后面无论生成 10 个按钮、20 个提示框，还是整套剧情 UI，都还能维持统一和可维护。
